# 문체 규칙 (본문, 표, 글머리표)

덱의 문장이 AI가 쓴 글처럼 읽히지 않게 하는 규칙이다. `scripts/check_deck.py`가 C 번호로 검사한다.
한국어 AI 문체의 패턴 분류는 im-not-ai의 것을 그대로 쓴다 (`vendor/im-not-ai/skills/humanize-korean/references/quick-rules.md`, 10개 범주 85개 패턴). 이 문서에는 슬라이드라는 형식 때문에 달라지는 점만 적는다.

## 문체 교정 단계의 절차

본문을 다 쓴 뒤, 검사(`check_deck.py`)를 한 번 통과시킨 다음에 한다.

1. `python3 scripts/copy_pass.py extract decks/<이름>/deck.html`: 덱의 글자를 `copy/before.txt`와 `copy/after.txt`로 꺼낸다.
2. `vendor/im-not-ai/skills/humanize-korean/references/quick-rules.md`를 읽고 `after.txt`의 줄을 교정한다. 아래의 "슬라이드에서 달라지는 점"이 quick-rules보다 우선한다.
3. `python3 scripts/copy_pass.py apply decks/<이름>/deck.html`: 교정한 줄을 덱에 반영한다. 수치가 달라졌거나 줄이 25%를 넘게 길어지면 반영을 거부한다. 반영 뒤에는 im-not-ai의 구조 게이트가 변경률을 보고한다.
4. `check_deck.py`와 `check_layout.mjs`를 다시 통과시킨다.

발표 대본, 소개서의 줄글, 메일 본문처럼 **문장으로 이어지는 글**은 이 절차 대신 `/humanize-korean` 스킬을 그대로 쓴다. 그 스킬은 줄글을 전제로 정량 지표와 게이트를 계산한다.

## 슬라이드에서 달라지는 점

| 번호 | 규칙 | 이유 | 판정 |
|---|---|---|---|
| C1 | 자리표시자(`{{ }}`)를 남기지 않는다 | 미완성 덱이 나가는 것을 막는다 | FAIL |
| C2 | 경어체(`~습니다`, `~해요`)를 쓰지 않는다 | 슬라이드는 말이 아니라 문서다. 경어체는 분량을 늘리고 제안서 투로 읽힌다 | FAIL |
| C3 | 한 덩어리(글머리표 한 줄, 표의 한 칸)에 한 문장만 쓴다. 110자를 넘기지 않는다 | 두 문장이 되면 글머리표 두 줄로 나누는 편이 읽기 쉽다 | WARN |
| C4 | 한 목록 안에서 문장 끝을 한 가지로 맞춘다. 기본은 헤드메시지와 같은 명사형이다 (`~ 확인`, `~ 필요`, `~ 불가`). `~함/~임`과 섞지 않는다 | 끝이 섞이면 여러 사람이 쓴 것처럼 읽힌다 | WARN |
| C5 | 항목이 하나뿐인 목록을 만들지 않고, 한 목록에 6개를 넘기지 않는다. 4개 이상이면 상위 묶음 둘로 나눌 수 있는지 본다 | 글머리표는 둘 이상을 나열할 때만 쓴다 | WARN |
| C6 | 엠대시(—)와 이모지를 쓰지 않는다. 라벨과 설명은 콜론으로, 보충은 쉼표나 문장으로 잇는다 | AI 문체의 가장 흔한 표시다 | FAIL |
| C7 | `harness/lexicon.json`의 `body_warn`에 있는 낱말을 줄인다 (빈 강조, 명사화된 업무 용어, 외래어 남용, 번역투, 상투적 연결, 추상적 덧말, 자기 미화) | 아래 표 참조 | WARN |
| C8 | 괄호를 한 장에 5개 넘게 쓰지 않는다 | 보충 설명이 많다면 구조(표의 열)로 풀어야 한다 | WARN |
| C9 | 주어와 서술어를 떨어뜨리지 않는다. `효율 향상`, `연계 강화`처럼 낱말만 남기지 않고 누가 무엇을 어떻게 하는지 적는다 (`담당자가 제품 등록을 직접 처리`) | 압축한 낱말은 쓴 사람만 뜻을 안다. 명사형 종결과 압축은 다르다 | 눈으로 확인 |
| C10 | 한 자료에서 한 개념은 한 낱말로 부른다 (이용자와 사용자, 릴스와 숏폼을 섞지 않는다). 줄임말은 처음 나올 때 풀어 쓴다 | 낱말이 바뀌면 다른 대상으로 읽힌다 | 눈으로 확인 |
| C11 | 글머리표마다 관점을 달리한다. 같은 말을 바꿔 쓴 줄을 나란히 두지 않는다. 읽는 사람이 이미 아는 사실을 줄로 만들지 않는다 | 줄 수로 내용의 빈약함을 가리는 것처럼 읽힌다 | 눈으로 확인 |
| C12 | 제품이 자동으로 하는 일을 적을 때는 사람이 판단하는 지점을 함께 적는다 | 자동화만 강조하면 통제할 수 없는 제품으로 읽힌다 | 눈으로 확인 |

## 줄일 낱말과 바꾸는 방법 (C7)

| 유형 | 예 | 바꾸는 방법 |
|---|---|---|
| 빈 강조 | 매우, 획기적, 압도적, 강력한, 탁월한 | 지운다. 강조하려는 내용을 수치로 적는다 |
| 명사화된 업무 용어 | 최적화, 효율화, 고도화, 극대화, 제고, 창출 | 실제로 일어나는 일을 동사로 적는다 (`탐색 최적화` → `검색 횟수를 5회에서 1회로 감소`) |
| 외래어 남용 | 솔루션, 인사이트, 니즈, 페인포인트, 심리스 | 한국어 낱말로 바꾼다 (`니즈` → `필요`, `인사이트` → `알게 된 점`) |
| 번역투 | ~를 통해, ~에 대한, ~에 있어, ~로 인해, ~하는 것이 가능 | 조사와 동사로 푼다 (`숏폼을 통해 발견한` → `숏폼에서 발견한`, `제품에 대한 후기` → `제품 후기`) |
| 상투적 연결 | 또한, 나아가, 뿐만 아니라, 이를 통해, 결론적으로 | 지운다. 글머리표의 순서와 들여쓰기가 관계를 나타낸다 |
| 추상적 덧말 | 다양한, 새로운, 핵심적인, 효과적인, ~ 측면에서 | 지우거나 구체적인 대상으로 바꾼다 (`다양한 채널` → `네이버, 유튜브, 쿠팡`) |
| 자기 미화 | 선도하는, 함께 성장, 세상을 바꾸는, 가치를 전달 | 지운다. 실적과 사실을 적는다 |

## 지키는 것

- 문체 교정은 내용을 바꾸지 않는다. 수치, 고유명사, 인용, 법률과 제도의 이름은 한 글자도 바꾸지 않는다 (`copy_pass.py`가 수치를 대조한다).
- 헤드메시지는 문체 교정에서 문형을 바꾸지 않는다. 헤드메시지를 고치려면 `headline-rules.md`의 절차로 돌아가 통독을 다시 한다.
- 지적을 받은 표현은 `harness/lexicon.json`에 한 줄 추가한다. 규칙 문서에만 적으면 다음 덱에서 같은 표현이 다시 나온다.
