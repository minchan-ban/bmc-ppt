# 로고 수집과 사용

고객사, 제휴사, 투자사, 경쟁사의 로고를 찾아 배경이 투명한 PNG로 만드는 절차와, 덱에 넣을 때의 규칙이다.
도구는 `scripts/logo.py`이고, 만든 로고는 `assets/logos/`에 모인다.

## 절차: 통과할 때까지 되풀이한다

```
후보 수집 → 배경 제거 → 자동 검사(Q1~Q7) → 미리보기를 눈으로 확인 → (맞지 않으면 후보나 방식을 바꿔 다시)
```

1. **수집과 자동 검사**
   ```bash
   .venv/bin/python scripts/logo.py get "<회사 이름>" --site <도메인> [--deck decks/<이름>]
   ```
   Chrome으로 홈페이지를 열어 머리 영역의 로고를 찾고, 위키미디어 공용에서 이름이 맞는 파일을 예비 후보로 더한다. 후보를 점수 순서로 하나씩 처리하고, 자동 검사를 처음 통과한 후보를 쓴다. 한 후보가 실패하면 배경 제거 방식을 바꿔 한 번 더 시도한 뒤 다음 후보로 넘어간다.
2. **미리보기를 Read로 직접 본다** (`assets/logos/_preview/<이름>.png`). 자동 검사는 그 회사의 로고가 맞는지 알지 못한다. 아래 다섯 가지를 확인한다.
   - 그 회사의 로고가 맞는가 (홈페이지에 실린 다른 회사의 로고, 이름이 비슷한 다른 회사, 예전 로고가 아닌가)
   - 워드마크까지 있는가 (심벌만 있는 앱 아이콘이 아닌가)
   - 글자 안쪽의 막힌 공간(o, a, ㅁ)이 뚫려 있는가, 반대로 로고 안의 흰 글자가 지워지지 않았는가
   - 어두운 바탕에서 흰 테두리가 남지 않는가
   - 흰 바탕에서 보이는가 (흰색 로고가 아닌가)
3. **맞지 않으면 다시 한다.** 무엇이 틀렸는지에 따라 바꿀 것이 다르다.

   | 미리보기에서 본 문제 | 다시 할 때 |
   |---|---|
   | 다른 회사의 로고이거나 심벌만 있다 | 미리보기 아래쪽 후보 번호를 보고 `--pick N` |
   | 해상도가 낮다 (`Q4` WARN, "해상도가 더 높은 통과 후보" 안내) | 같은 로고인지 확인하고 `--pick N` |
   | 글자 안쪽에 흰 배경이 남았다 | `--mode key` |
   | 로고 안의 흰 글자가 지워졌다 | `--mode connected` |
   | 흰색 로고라 흰 슬라이드에서 보이지 않는다 (`Q5` WARN) | `--mono "#18181C"`로 단색판을 만들거나, 어두운 판을 `--wiki`로 찾는다 |
   | 후보가 전부 실패했다 | `--wiki "<영문 회사명> logo"`, 그래도 없으면 회사의 브랜드 자료 페이지에서 받은 파일을 `--file`로, 주소를 알면 `--url`로 |
   | 사진이거나 무늬 배경이다 (`Q0`) | 이 도구로는 지울 수 없다. 다른 출처를 찾는다 |
4. **세 번 다시 해도 맞는 로고를 얻지 못하면 멈추고 사용자에게 묻는다.** 로고 파일을 받을 수 있는지, 그 회사를 로고 없이 이름으로 적을지를 정한다. 비슷한 로고를 그려서 대신하지 않는다.
5. 끝나면 `python3 scripts/logo.py sheet`로 모은 로고 전체를 한 장으로 보고, 크기와 색의 균형을 확인한다.

## 자동 검사

| 번호 | 검사 | 판정 |
|---|---|---|
| Q0 | 가장자리가 단색이어야 배경을 지울 수 있다 | FAIL |
| Q1 | 투명한 영역이 4%~97.5% 사이 (배경이 안 지워졌거나 로고까지 지워진 경우를 잡는다) | FAIL |
| Q2 | 배경을 지운 뒤 가장자리의 97% 이상이 투명 (로고가 잘렸거나 배경이 남은 경우) | FAIL |
| Q3 | 보이는 영역 중 반투명이 35% 이하 (흐린 이미지, 그라데이션 배경) | FAIL |
| Q4 | 긴 변 120px 이상. 400px 미만이면 크게 쓰기 어렵다 | FAIL / WARN |
| Q5 | 거의 흰색인 로고 | WARN |
| Q6 | 가로세로 비율이 12:1을 넘는 띠 이미지 | WARN |
| Q7 | 정사각형을 거의 채운 이미지 (앱 아이콘이나 심벌) | WARN |

출처 주소, 쓴 방식, 검사 결과, 시도한 후보 전체가 `assets/logos/<이름>.json`에 남는다.

## 덱에 넣는 규칙

| 번호 | 규칙 | 이유 |
|---|---|---|
| G1 | **실어도 되는 회사만 싣는다.** 고객사와 제휴사의 로고는 사용자가 "실어도 된다"고 확인한 회사만 넣는다. 확인되지 않은 회사는 로고를 받아 두더라도 덱에 넣기 전에 묻는다 | 로고는 상표이고, 덱에 실으면 거래 관계를 공개하는 것이 된다. 계약에 따라 공개가 금지된 경우가 있다 |
| G2 | **관계를 사실대로 적는다.** 축 제목이나 헤드메시지에 `도입 고객`, `협의 중`, `시범 운영`을 구분해 적고, 협의 중인 회사를 고객으로 보이게 하지 않는다. 기준 시점을 적는다 | 투자자와 구매 담당자는 로고 모음을 실적으로 읽는다 |
| G3 | **로고를 고치지 않는다.** 색을 바꾸거나 비율을 늘이거나 일부를 잘라 쓰지 않는다. 단색판(`--mono`)은 로고 모음에서 여러 회사의 색을 맞출 때만 쓰고, 한 모음 안에서는 전부 원래 색이거나 전부 단색이어야 한다 | 변형된 로고는 그 회사의 브랜드 규정을 어기고, 섞어 쓰면 일부만 강조된다 |
| G4 | **크기는 칸에 맞춘다.** 로고 모음(`p25`)의 칸은 크기가 같고 로고는 높이와 너비 제한 안에 들어간다. 로고마다 크기를 따로 지정하지 않는다 | 높이만 맞추면 가로로 긴 로고가 훨씬 크게 보인다 |
| G5 | **순서에 기준을 둔다.** 가나다순, 도입 순, 업종별 가운데 하나로 놓고 그 기준을 축 제목 오른쪽에 적는다 | 기준 없는 순서는 앞에 놓인 회사를 강조하는 것으로 읽힌다 |
| G6 | **경쟁사의 로고는 비교표의 열 제목이나 포지셔닝의 점 옆에만 쓴다** (`img.lgi`). 경쟁사를 깎아내리는 문구 옆에 로고를 놓지 않는다 | 비교 광고로 읽힐 수 있다 |
| G7 | **출처를 남긴다.** `assets/logos/<이름>.json`을 지우지 않는다 | 나중에 로고가 바뀌었는지, 어디서 받았는지 확인할 수 있어야 한다 |

## 덱에 넣는 방법

- 로고 모음: 부품 `p25`. `.lg` 안의 `<span>`을 `<img src="assets/logos/<이름>.png" alt="<회사 이름>">`으로 바꾼다. 칸 수는 `.logos`에 `c4`, `c6`을 붙여 바꾼다.
- 표의 칸이나 열 제목: `<img class="lgi" src="..." alt="...">`
- 표지에 상대 회사 로고를 함께 놓기: 표지의 `.cv-meta` 위에 `<div class="cv-with"><img src="..." alt="..."><span>귀중</span></div>`
- 덱 폴더에 복사: `logo.py get ... --deck decks/<이름>`이 `decks/<이름>/assets/logos/`에 복사한다. `deck.html`에서는 `assets/logos/...`로 가리킨다.
- PPTX에는 원본 PNG가 그림으로 들어가서 크기를 키워도 원본 해상도까지 선명하다. Figma용 HTML에는 파일 안에 포함되어 올라간다.
- `alt`에 회사 이름을 적는다. PowerPoint의 선택 창에 그 이름으로 표시된다.
