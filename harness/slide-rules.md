# 슬라이드 규칙 (구성, 배치, 표, 도표, 색)

컨설팅과 PE 자료의 관례를 이 프로젝트에 맞게 정리했다. 원전은 `vendor/consulting-pptx-skill/references/slide-rules.md`(일본어)이고, 여기에는 이 시스템에서 실제로 지키고 검사하는 규칙만 옮겼다.
헤드메시지는 `headline-rules.md`, 문장은 `copy-rules.md`가 정본이다.

## AI가 만든 자료처럼 보이는 원인

출력 전에 아래 다섯 가지만은 모든 장에서 눈으로 확인한다.

1. **떠 있는 상자**: 표, 단, 도표의 구조에 속하지 않고 혼자 놓인 라벨, 배지, 작은 상자
2. **카드 나열**: 같은 모양의 둥근 카드 3~4장에 아이콘, 제목, 설명을 넣어 늘어놓은 구성
3. **의미 없는 채움과 장식**: 뜻을 설명할 수 없는 배경색, 그라데이션, 그림자, 둥근 모서리, 아이콘
4. **맨 아래 결론 띠**: 슬라이드 아래쪽에 `핵심 포인트`, `Key Takeaway` 같은 띠를 두고 결론을 다시 적는 구성
5. **지나친 압축**: 주어와 서술어를 뺀 낱말 묶음(`효율 향상`, `연계 강화`)만으로 채운 본문

## 구성

| 번호 | 규칙 | 이유 |
|---|---|---|
| S10 | 한 장에 주장 하나만 담는다. 주제가 둘이면 두 장으로 나눈다 | 헤드메시지 하나가 본문 전체를 대표해야 한다 |
| S11 | 왼쪽에 사실(표, 도표)을 두고 오른쪽에 그 사실이 뜻하는 바를 둔다. 전제, 정의, 이유처럼 흐름의 앞에 오는 것이 왼쪽이다 | 읽는 사람은 왼쪽에서 오른쪽으로 "왜, 무엇이, 그래서"의 순서로 읽는다 |
| S12 | 좌우 단에는 각각 열 제목을 두고, 높이와 괘선 위치를 맞춘다. 열 제목은 그것만 읽어도 뜻이 통하는 명사구로 쓴다 (`그래서 ~`로 시작하지 않는다) | 두 단의 관계가 열 제목에서 읽혀야 한다 |
| S13 | 한 단에 제목을 두 개 쌓지 않는다. 단 안의 구조는 글머리표의 들여쓰기로 나타낸다 | 같은 축의 제목을 두 번 보이는 것과 같다 |
| S14 | 위아래로 관계없는 내용을 쌓지 않는다. 묶음은 좌우로 나눈다 | 아래 단과 위 단의 관계가 읽히지 않는다 |
| S15 | 문제나 위험을 보인 장에는 대응을 함께 싣는다 | 우려만 늘어놓은 장은 판단에 쓸 수 없다 |
| S16 | 본문이 10장을 넘는 덱에만 핵심 요약(p02)과 장 구분(p03)을 둔다. 핵심 요약의 각 행은 본문 한 장에 대응시킨다 | 짧은 덱에서 요약과 장 구분은 분량만 늘린다 |
| S17 | 마지막 장은 연락처만 있는 뒤표지다. 요청이나 결론은 그 앞의 일반 슬라이드에 헤드메시지와 표로 싣는다 | 결론 띠와 같은 이유다 |
| S18 | 본문 영역의 55% 이상을 내용으로 채운다. 비면 내용을 더하거나 정보량에 맞는 부품으로 바꾸고, 그래도 적으면 세로 가운데에 둔다. 띠, 아이콘, 장식으로 채우지 않는다 | 빈 공간은 정보가 부족하거나 부품이 맞지 않는다는 신호다 (`check_layout` L5) |

## 표

| 번호 | 규칙 | 이유 |
|---|---|---|
| S20 | 같은 모양의 상자를 나열하지 말고, 행(항목)과 열(관점)이 있는 표로 만든다. 두 상자를 좌우로 비교하게 하지 않는다 | 축이 있어야 항목끼리 비교가 된다 |
| S21 | 머리글은 채움 없이 굵은 글자와 굵은 아래 괘선으로 나타낸다. 행 사이는 옅은 괘선 한 줄이고, 마지막 행 아래에는 괘선을 긋지 않는다. 줄무늬 배경을 쓰지 않는다 | 괘선은 나눌 대상이 있는 자리에만 긋는다 |
| S22 | 행은 맨 왼쪽 축이 정의한 집합의 원소로만 채운다. 성격이 다른 결론 행을 마지막에 붙이지 않는다 | 축이 `고객 유형`이면 모든 행이 고객 유형이어야 한다 |
| S23 | 주장에 쓰이지 않는 열은 두지 않는다. 열 이름은 그 칸에 무엇이 적혀 있는지 가리키는 구체적인 명사로 쓴다 | 불필요한 열은 읽는 사람을 다른 비교로 이끈다 |
| S24 | 칸 안의 설명이 두 건 이상이면 글머리표로 나눈다. 한 칸에 문장을 두 개 이상 이어 쓰지 않는다 | 칸 안의 긴 문장은 읽히지 않는다 |
| S25 | 해당 없는 칸은 비우지 않고 `해당 없음`이나 `-`를 적고 `td.na`로 옅게 처리한다 | 빈칸은 누락인지 해당 없음인지 알 수 없다 |
| S26 | 경쟁 비교표에는 상대가 앞서는 축을 반드시 넣는다. 자사 열만 항상 강조하지 않고, 기호의 뜻을 범례에 적는다 | 자사가 모든 축에서 앞서는 표는 신뢰를 잃는다 |

## 도표

| 번호 | 규칙 | 이유 |
|---|---|---|
| S30 | 추이, 구성비, 분포는 도표로 그린다. 수치를 표에 넣는 것으로 대신하지 않는다 | 추세와 비율은 도형으로 봐야 한눈에 읽힌다 |
| S31 | 도표 하나에 주장 하나. 강조색은 헤드메시지가 말하는 항목 하나에만 쓰고 나머지는 회색 계열로 둔다 | 강조가 여럿이면 어느 것도 강조되지 않는다 (`check_layout` L6) |
| S32 | 도표 바로 위에 축 제목(`.axh`)을 둔다. 왼쪽에 지표 이름, 오른쪽에 단위와 기간 | 무엇을 잰 값인지 모르면 수치를 읽을 수 없다 |
| S33 | 수치가 있는 도표에는 출처 줄을 둔다. 자사 집계에도 기간과 측정 조건을 적는다 | `check_deck` S1 |
| S34 | 막대는 0에서 시작한다. 비율처럼 최댓값이 정해진 지표는 전체 범위로 그린다 | 축을 자르면 차이가 과장된다 |
| S35 | 도표는 부품의 div 도형으로 그린다. SVG와 이미지로 만든 도표를 쓰지 않는다. 원형, 도넛, 꺾은선, 영역은 기본 차트 부품(p58~p61)으로만 그린다. 원형과 도넛은 조각 5개 이하이고 합이 전체가 되는 값에만 쓰며, 조각끼리 크기를 비교해야 하면 가로 막대(p06)로 그린다 | SVG는 PPTX에서 그림으로 변환되어 수치를 고칠 수 없다. 기본 차트 부품은 PowerPoint 기본 차트가 되어 수치를 고칠 수 있다. 각도와 면적은 길이보다 비교하기 어렵다 (`check_deck` S7) |
| S36 | 배율과 차이를 말할 때는 기준이 되는 항목을 도표에서 알 수 있게 한다 | `2.1배`만으로는 무엇의 무엇에 대한 배율인지 알 수 없다 |
| S37 | 크기를 원의 면적으로 보일 때(p31, p49)는 지름이 아니라 면적을 값에 비례시킨다. 비례시킬 수 없으면 출처 줄에 `원의 크기는 축척이 아님`을 적는다 | 지름을 값에 비례시키면 큰 값이 제곱으로 과장된다 |
| S38 | 같은 지표를 여러 도표로 나눠 그릴 때(p51)는 모든 도표의 세로 축 범위를 같게 둔다 | 축이 다르면 막대 높이로 대상끼리 비교할 수 없다 |
| S39 | 실적과 전망을 한 도표에 넣을 때(p07, p50)는 전망에 `fc`를 붙여 점선으로 구분하고, 성장률은 실적 구간과 전망 구간을 나눠 적는다 | 전망을 실적처럼 그리면 계획이 성과로 읽힌다 |

## 색과 장식

| 번호 | 규칙 | 이유 |
|---|---|---|
| S40 | 색은 토큰(`var(--primary)`, `var(--accent)` 등)으로만 쓴다. HEX를 직접 쓰지 않는다 | 팔레트를 바꿔도 덱 전체가 함께 바뀌어야 한다 (`check_deck` S5) |
| S41 | 채움에는 뜻이 있어야 한다. 채운 도형의 색이 다르면 같은 장에 범례를 둔다 | 뜻 없는 강조는 장식으로 읽힌다 |
| S42 | 채운 도형에는 테두리를 두지 않는다. 둥근 모서리, 그림자, 그라데이션을 쓰지 않는다 (원은 충족도 기호와 매트릭스의 점에만 쓴다) | 컨설팅과 PE 자료의 관례이고, 장식은 AI가 만든 자료의 흔한 표시다 |
| S43 | 빨강(`--neg`)은 악화와 불가를 나타낼 때만 쓴다. 신호등 3색 표를 쓰지 않는다 | 뜻을 가진 색은 그 뜻으로만 쓴다 |
| S44 | 이모지와 장식 아이콘을 쓰지 않는다 | `check_deck` C6 |
| S45 | 제품 화면 이미지는 가공하지 않고 그대로 넣는다 | 목업 장식은 실제 제품이 아니라는 인상을 준다 |
| S46 | 슬라이드 밖으로 잘려 나가게 두는 것은 표지와 장 구분의 로고·장식 이미지뿐이고, 그 요소에 `bleed` 클래스를 단다. 글자와 도표에는 쓰지 않는다 | 의도한 잘림만 화면 검사(L3)에서 빼기 위해서다. 본문에서 잘린 요소는 실수다 |

## 글자 크기와 굵기

글꼴은 Pretendard 하나만 쓴다. 굵기의 용도는 `design/typography.md`에 있다.

- 굵기는 `var(--w-head)` 같은 토큰이나 부품의 클래스로 지정한다. 인라인으로 글꼴과 굵기를 지정하지 않는다.
- 본문 안의 강조는 `<b>`로 한 장에 한두 군데만 쓴다. 모든 칸이 같은 농도로 보이지 않게 하되, 강조가 많으면 강조가 아니다.
- 본문 글자를 줄여서 내용을 욱여넣지 않는다. 넘치면 내용을 덜거나 두 장으로 나눈다.

## 변환 제약 (PPTX와 Figma에서 편집할 수 있게 하기 위한 제약)

- CSS `transform`, `::before`/`::after`로 그린 장식, SVG, `color-mix()`를 쓰지 않는다. 변환기가 재현하지 못하거나 그림으로 바꾼다.
- 목록은 `ul` 안에 `li`만 두고, `li` 안에는 글자와 중첩 목록만 둔다. 이 형태여야 글머리표가 문단 여러 개인 글상자 하나로 변환된다.
- 슬라이드 한 장은 `section.slide` 하나다. 덱의 원본은 항상 `deck.html`이고, PPTX와 Figma에서 고친 내용은 원본에 반영되지 않는다.
